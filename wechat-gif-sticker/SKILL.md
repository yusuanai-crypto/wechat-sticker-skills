# WeChat-GIF-Sticker

## 默认创作档案

除非用户在本次请求中明确覆盖，否则采用以下规格：

- 用途：微信群个人粉丝交流。
- 风格：Q 版半身贴纸，保留人物最有辨识度的脸型、发型、眼镜、服装和配饰。
- 动画：优先复现多张截图之间真实可见的手势、表情和道具变化；轻微、短促、可无缝循环，人物身份稳定优先于动作复杂度。
- 背景：真正透明；人物使用白色贴纸描边。
- 文字：逐字采用用户提供的精确文本，不让图像模型直接生成汉字。默认采用粗手写漫画标题字：主文字白色，最多一个核心词组使用黄橙色，外加粗黑内描边、较细白色外描边和轻微右下灰影；整体紧凑、有动势，并在底部轻叠人物下缘。同一 GIF 的全部帧锁定同一文字样式。
- 构图：正方形；先生成高分辨率透明 PNG 母图，再确定性地合成 GIF。
- 禁止无请求添加频道标志、水印、额外人物或新口号。

用户当次明确要求优先于这些默认值，但不要把一次性的变化写回本 Skill，除非用户要求更新默认偏好。

## 必需输入

开始制作前必须具备：

1. 至少一张清晰人物截图；多张截图可共同作为身份参考。
2. 每个表情对应的精确文字。

动作、情绪和文字位置可以省略：有多张截图时，按用户给出的顺序把截图视为动作关键帧，并从可见差异提取动作；只有一张截图时，才根据文字选择克制的备用动画。若截图顺序无法判断且顺序会改变含义，询问一次。若缺少截图或文字，也只询问一次；其余细节按默认档案推进。

如果截图来自本地文件，先用图像查看工具检查。把截图标记为“人物身份参考”，而不是要逐像素修改的编辑目标。不要根据外貌推断敏感属性。

## 制作流程

1. 阅读 [references/style-spec.md](references/style-spec.md)，据此选择动作、构图和生成提示词。
2. 检查全部截图，分别提炼：
   - 多张截图中保持不变的身份锚点、服装、人物比例和构图；
   - 相邻截图之间发生变化的手势、手臂位置、表情、视线、身体姿态和道具状态。
3. 若 `assets/character-style-anchor.png` 存在，先检查并把它作为画风与人物比例的主参考，新截图作为服装、表情或角度的辅助参考。若不存在，不要阻塞首次制作。
4. 有两张或更多动作截图时，生成动作关键帧序列：
   - 先根据第 1 张截图生成 1024×1024 的透明 Q 版首帧；
   - 后续帧必须以首帧或上一帧为编辑目标，以对应截图为动作参考；锁定脸、发型、服装、色板、线条、人物大小、左右位置和相机视角，只修改动作差异；
   - 不要把各帧当成互不相关的新图分别生成。
5. 只有一张截图时，才生成单张透明母图，并在用户未指定具体动作时使用轻微备用动画。不得在已有多张动作参考图时，用整个人物上下跳动、整体缩放或整图摇晃代替动作变化。
6. 检查每张关键帧的人物相似度、透明度、手部、轮廓和服装，并逐帧对照截图确认动作差异真实存在。只针对一个明确问题迭代，避免无关漂移。
7. 将选定关键帧复制到当前工作区的 `output/wechat-gif-sticker/<batch-name>/keyframes/`，按 `frame-01.png`、`frame-02.png` 顺序命名。不要把项目使用的唯一副本留在默认生成目录。
8. 检查已确认首帧，按 `style-spec.md` 组合粗手写字形、白色主字、黄橙关键词、黑色内描边、白色外描边和右下灰影。只在原文中存在明确核心词时，用 `--highlight-text` 指定一个连续且只出现一次的精确子串；不得为了高亮改写文案。若默认字形、层次或位置不适合画面，使用 `--font`、`--text-fill`、`--text-stroke`、`--text-outer-stroke`、`--highlight-fill`、`--text-shadow` 和 `--caption-lift` 显式覆盖。成套表情优先复用已确认的文字样式。
9. 有两个或更多关键帧时，使用 `scripts/build_action_gif.py` 添加统一人物白边、精确文字并按关键帧顺序合成；只有一个关键帧时才使用 `scripts/build_gif.py` 的整图轻微动画。默认同时导出：
   - 512×512 质量版；
   - 240×240 微信紧凑版。
10. 检查 GIF 的动作变化、首尾循环、人物漂移、文字准确性、粗手写漫画感、双层描边完整度、关键词高亮克制程度、文字与人物的轻叠关系、小尺寸可读性、透明边缘和文件体积。动作变化至少应体现在手势、表情、姿态或道具状态之一，而不是仅改变整张图的位置或大小。必要时先调整文字样式，再减少尺寸、过渡帧或调色板颜色。
11. 交付 GIF、关键帧预览、关键帧 PNG 路径，并报告实际尺寸、帧数、文件体积、动作变化、文字字体与配色，以及最终生成/编辑提示词。

## 动作关键帧合成

当存在两张或更多动作关键帧时，优先使用 `scripts/build_action_gif.py`。脚本保持整张构图固定，只在关键帧之间切换或添加短过渡，不对整组人物施加上下跳动：

```powershell
python scripts/build_action_gif.py `
  --input output/wechat-gif-sticker/demo/keyframes/frame-01.png `
  --input output/wechat-gif-sticker/demo/keyframes/frame-02.png `
  --output output/wechat-gif-sticker/demo/chigua-512.gif `
  --contact-sheet output/wechat-gif-sticker/demo/chigua-keyframes.png `
  --text "你在吃瓜吗?" `
  --highlight-text "吃瓜" `
  --size 512
```

默认使用往返循环：第 1 个动作 → 最后一个动作 → 第 1 个动作。脚本默认使用白色主字、黄橙关键词、粗黑内描边、白色外描边和右下灰影；文字颜色、描边、字体和画布位置在所有帧中保持固定。若需覆盖，传入十六进制颜色或明确宽度参数；`auto` 仅作为用户要求随画面取色时的可选值。

## 单帧备用合成

仅当只有一个动作参考帧时，才使用 `scripts/build_gif.py`。示例：

```powershell
python scripts/build_gif.py `
  --input output/wechat-gif-sticker/demo/masters/hao-ye.png `
  --output output/wechat-gif-sticker/demo/hao-ye-512.gif `
  --preview output/wechat-gif-sticker/demo/hao-ye-preview.png `
  --text "好耶！" `
  --animation bounce `
  --size 512
```

若系统没有命令名为 `python` 的解释器，使用当前环境提供的 Python 可执行文件。脚本依赖 Pillow；先检测依赖，缺失时再说明所需安装操作，不要静默安装。

## 首次校准与固定母版

首次先制作两个代表性表情：一个常规、一个夸张。用户确认后再扩充整套。

如果用户明确要求“以后都沿用这个人物/画风”，可把确认后的无文字透明母图复制为 `assets/character-style-anchor.png`。写入已安装的 Skill 可能需要文件权限；执行前准确说明目标。未获此要求时，只在本次输出目录保留候选母版。

## 边界

- 默认仅按用户声明的个人粉丝交流用途处理。若用途改为销售、广告或官方宣传，提醒其自行确认人物肖像、截图与标志的使用授权。
- 不把静态截图扩展为仿真人讲话或误导性真人视频；本 Skill 的输出应保持明显的 Q 版表情包属性。
- 多张截图提供了动作变化时，不得用整图位移、缩放、旋转或抖动替代截图中的动作变化。
- 不覆盖既有输出文件；除非用户明确要求替换，否则使用新批次目录或版本化文件名。
