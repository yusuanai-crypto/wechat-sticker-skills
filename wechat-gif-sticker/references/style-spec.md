# 风格与动作规范

## 固定视觉语言

- 画面：正方形、Q 版半身或大头半身，人物主体清楚，缩小后仍可辨认。
- 人物：保留稳定可见的脸型、发型、眼镜、服装色块和标志性配饰；减少皮肤纹理与写实细节。
- 线条：干净的深色轮廓，色块清楚，阴影简洁。
- 外沿：GIF 合成阶段给人物统一添加白色贴纸描边，生成母图时不要画第二层外沿。
- 背景：真实 alpha 透明，不要棋盘格、纯色底、场景、地面或投影。
- 文案：逐字匹配用户文本，不由图像模型绘制。默认使用粗手写漫画标题字，采用“白色主字＋黄橙关键词＋粗黑内描边＋白色外描边＋右下灰影”的贴纸层次。
- 构图安全区：人物与画布边缘留足动画位移和白边空间；字幕位于顶部或底部，不压住眼睛和主要表情。

## 文字风格匹配

先看已确认的 Q 版首帧，再决定文字尺寸和叠放位置；默认保持以下视觉结构：

- 字形：首选粗重、紧凑、带自然手写起伏的中文漫画标题字，字面要饱满且略有斜势。避免幼圆、宋体、仿宋、细黑体、规则几何黑体和纤细书法字；不要随机逐字旋转、缩放或混搭字体。
- 主次配色：普通文字使用白色；原文中若有明确核心词，只高亮一个连续且只出现一次的精确子串，使用暖黄或黄橙色，默认 `#FFB21A`。短文案或没有明确核心词时保持全白，不为了配色改字、添字或拆词。
- 描边层次：文字先加约为字号 11% 的粗黑内描边，再加约为字号 6% 的白色外描边。黑边负责清楚有力，白边负责把整组字从人物与透明背景中托起；两层都必须连续，不能互换顺序。
- 阴影：在右下方添加约为字号 6% 偏移的短灰影，颜色接近 `#626262A0`。阴影只增加贴纸立体感，不做长投影、发光、模糊光晕或大面积底板。
- 版式：短文案优先单行、紧凑居中，整体略有手写动势。底部字幕可上提约画布宽度的 3%，轻叠人物肩部或下缘，但不得遮挡眼睛、嘴部、核心手势和关键道具；顶部字幕不强行叠人物。
- 可读性：240×240 版本中仍应一眼读清白字、黄橙关键词、黑内描边和白外描边；若拥挤，先缩小字号，再减少高亮，最后才换行。
- 一致性：一个 GIF 的所有帧，以及同一套已确认的表情，使用相同字体、主字色、高亮色、双层描边、阴影和相对字号，除非用户明确要求变化。

合成脚本在 Windows 上优先使用系统“华文行楷”，再回退到华文新魏、华文琥珀和通用粗体。`--highlight-text` 只接受原文中唯一出现的单行子串；需要替换字体时，使用 `--font` 指向有权使用且支持中文的粗手写 `.ttf` 或 `.ttc` 文件。默认颜色已按上述层次固定；只有用户明确要求随画面取色时，才对 `--text-fill`、`--text-stroke` 或其他颜色参数传入 `auto`。必须同时检查 512×512 和 240×240 预览。

## 多截图动作关键帧

两张或更多截图如果来自同一段动作，按用户提供顺序作为关键帧参考。先区分“必须锁定”和“允许变化”：

- 必须锁定：脸、发型、眼镜、服装、色板、线条、人物左右关系、画布位置、镜头距离、背景透明度和字幕安全区。
- 允许变化：手臂和手掌位置、手势、嘴眼表情、头部朝向、身体姿态，以及瓜子、杯子等道具的持握状态。
- 后续关键帧使用图像编辑流程，从首帧或上一帧修改动作；不要独立重新生成整个人物。
- 两张截图中若有两个人，两个人的动作都要逐一比对，不能只改变其中一人，也不能把人物合并。
- GIF 画布保持静止；动作来自关键帧内部变化。整图上下跳、整体缩放、左右摇摆不算动作关键帧。
- 关键帧变化较大时，允许添加 1–2 个短交叉过渡帧，但清晰的动作端点必须保留。

## 单截图备用动作映射

仅在只有一张截图且用户没有提供动作描述时，根据文字语气选择最轻的备用动作；用户指定动作时以用户要求为准。

| 情绪或语义 | 动画模式 | 说明 |
| --- | --- | --- |
| 好的、收到、明白、谢谢 | `bob` | 轻微上下点动 |
| 开心、好耶、开饭、庆祝 | `bounce` | 轻微弹跳 |
| 震惊、真的吗、啊？ | `pulse` | 轻微放大回弹 |
| 不要、拒绝、生气、急了 | `shake` | 小幅左右摇动 |
| 无语、疑惑、让我想想 | `sway` | 缓慢左右倾斜 |
| 晚安、困、放空 | `bob` | 更小幅度、较慢循环 |

## 首帧提示词模板

每个表情使用一份独立提示词，并明确列出输入图片角色。不要在不同表情之间省略身份不变量。

```text
Use case: style-transfer
Asset type: transparent animated-sticker master frame
Primary request: 根据人物参考截图，绘制用于微信群表情包的 Q 版半身贴纸人物母图，表现“<情绪/动作>”。
Input images: 图片 1..N 为同一人物的身份参考；如有风格母版，它是人物比例与画风主参考。
Subject: 保留 <从截图提炼的稳定身份特征>。
Style/medium: 干净的 Q 版数字插画，粗细一致的深色轮廓，简洁色块和轻阴影。
Composition/framing: 1024×1024 正方形，居中半身，给 <顶部/底部> 字幕留出安全区，四周留出动画位移空间。
Constraints: 真正透明背景；只出现一个人物；不包含任何文字；不包含水印、Logo、场景、地面或投影；人物身份与服装特征稳定。
Avoid: 写实照片感、复杂背景、额外肢体、手指错误、裁切头发、棋盘格假透明、文字乱码。
```

## 后续动作帧编辑模板

```text
Use case: identity-preserve
Asset type: transparent animated-sticker action keyframe
Primary request: 编辑首帧，仅把两个人的动作改成动作参考截图所示的下一时刻。
Input images: 图片 1 是要编辑的 Q 版首帧；图片 2 是前一动作参考；图片 3 是当前动作参考。
Action changes: <逐项描述左侧人物和右侧人物的手势、表情、视线、身体与道具变化>。
Invariants: 人脸身份、发型、眼镜、服装、手表、色板、线条、人物大小、左右位置、相机视角、透明画布和字幕安全区完全不变。
Constraints: 真正透明背景；只出现原有的人物；不包含文字、Logo、水印、场景、地面或投影。
Avoid: 整组人物上下移动或缩放、重新设计人物、改变服装、交换左右位置、增加肢体、手指错误、棋盘格假透明。
```

## 导出建议

- 质量版：512×512，每个动作端点停留 250–400 毫秒，端点之间可加 1–2 个短过渡帧，96–128 色起步。
- 微信紧凑版：240×240，保留全部动作端点，必要时先减少过渡帧，再减少颜色。
- GIF 的透明度是索引透明，不能保留平滑半透明边缘；白色描边可降低锯齿观感。
- 若文件过大，优先减少尺寸和帧数，其次减少颜色；不要先牺牲文字可读性。
- 关键词高亮、双层描边、阴影和字幕上提量只读取首帧并锁定，避免动画过程中字幕变色、跳位或闪烁。
- 如用户需要更高质量的通用版本，可额外提供动态 WebP，但必须保留其要求的 GIF。
